# Тестовое задание
## Описание

В сущность `tasks` добавлены поля:

- `task_type` — тип задачи (ежедневная, ежемесячная, на конкретную дату, переменная по чётным/нечётным дням)
- `schedule_at` — дата выполнения задачи
- `task_interval` — интервал повторения

```sql
CREATE TABLE IF NOT EXISTS tasks (
    id BIGSERIAL PRIMARY KEY,
    title TEXT NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    status TEXT NOT NULL,
    task_type TEXT NOT NULL,
    task_interval INT,
    schedule_at TIMESTAMPTZ NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_tasks_status ON tasks (status);
CREATE INDEX IF NOT EXISTS idx_tasks_task_type ON tasks (task_type);

## Типы задач (`task_type`) и логика поля `task_interval`

| `task_type`         | Значение `task_interval`                                                                 | Примечание |
|---------------------|------------------------------------------------------------------------------------------|-------------|
| `daily`             | Целое число дней, через которое задача повторяется (неотрицательное, не равно 0)          | Например, `1` – каждый день, `3` – раз в 3 дня. |
| `monthly`           | Число от 1 до 30 – день месяца, когда выполняется задача                                  | Интервал хранит день месяца. |
| `special_date`        | Не используется (можно `NULL`)                                                            | Выполнение строго в дату `schedule_at`. |
| `even_odd`   | `1` – нечётные дни, `2` – чётные дни                                                      | Задача выполняется только в дни с соответствующей чётностью. |

> Поле `task_interval` – универсальное, его значение интерпретируется динамически на основе `task_type`.
```
## Индексы

Для оптимизации запросов создан индекс:

- `idx_tasks_task_type` – по полю `task_type`

## Комментарии (ход решения)

### Универсальное поле `task_interval`

Поле сделано универсальным – его значение расшифровывается в коде в зависимости от `task_type`.

- **`daily`** – число дней между повторами (неотрицательное, не равно 0).  
  *Размышления:*  
  - Ввёл проверку на неотрицательность и `!= 0`.  
  - Думал, стоит ли ограничивать верхнюю границу (например, 30). Потому что при интервале >30 задача фактически перестаёт быть «ежедневной» и начинает напоминать ежемесячную.  
  - С другой стороны, можно было бы разрешить интервал «раз в 2 месяца», но это не укладывается в логику "ежедневной" задачи.  
  - **Вывод:** нужны чёткие требования от клиента. В текущей реализации верхняя граница не ограничена, но это отмечено как потенциальная проблема.

- **`monthly`** – число от 1 до 30 (день месяца).  
  Интервал хранит день, в который должна выполняться задача.

- **`even_odd`** – `1` = нечётные дни, `2` = чётные дни.

- **`special_date`** – интервал не используется, смотрим только `schedule_at`.

### Альтернативное архитектурное решение

Рассматривался вариант вынести `(task_type, task_interval)` в отдельную сущность (нормализация).  
Но показалось, что это приведёт к переусложнению кода для текущей задачи.  
Оставлено как есть, но с пониманием, что это компромисс.
